# Amazon Route 53

Amazon Route 53 is a highly available, scalable DNS web service. It is commonly used for:

1. **Domain registration** – register website names like `bms.com`.
2. **DNS routing** – direct internet traffic to the correct resources for your domain, so requests to `bms.com` or `web.bms.com` reach your application.
3. **Health checks** – regularly verify that your web server is healthy. If a resource becomes unhealthy, Route 53 can send alerts and reroute traffic to healthy endpoints.

## Hosted Zones

Hosted zones are containers for DNS records. Records define how traffic is routed for a domain such as `bms.com` and its subdomains, like `web.bms.com` or `cloud.bms.com`.

- **Public Hosted Zone**: routes traffic over the internet.
- **Private Hosted Zone**: routes traffic within an AWS VPC.

## Record types

Each DNS record includes a domain or subdomain name, a record type, and type-specific routing information.

- **A record** – routes traffic to a web server using an IPv4 address.
- **AAAA record** – routes traffic using an IPv6 address.
- **CNAME record** – points one domain name to another. You cannot create a `CNAME` for the root domain (`bms.com`), only for subdomains like `web.bms.com`. If a `CNAME` exists for a name, no other record type may be defined for that same name.
- **MX record** – defines mail servers for a domain, usually with multiple records and priority values.

## Routing policies

1. **Simple routing policy** – use for a single resource that handles traffic for a domain.
2. **Weighted routing policy** – distribute traffic across multiple resources using specified weights. This can also be used in private hosted zones.
3. **Failover routing policy** – configure active-passive failover. This is available for private hosted zones as well.
4. **Latency routing policy** – route users to the AWS region with the best latency when resources are deployed in multiple regions. Private hosted zones support this too.
5. **Geolocation routing policy** – route traffic based on the user’s geographic location. It can be used in private hosted zones.

## Health checks

Amazon Route 53 health checks monitor the health and performance of web applications, servers, and other resources. A health check can verify:

- the health of a specific resource, such as a web server,
- the status of another health check, or
- the status of an Amazon CloudWatch alarm.

## ARC and failover

With Amazon Application Recovery Controller (ARC), you can configure routing control health checks and DNS failover records to manage application traffic failover.
